## Failure Attribution per item (earliest-wrong layer)

- **HA-001**: Frontend/CSS — two Library `<ul>` elements had no `list-style: none` rule (one had no class at all; one had a class with no matching CSS rule).
- **HA-002**: Frontend integration — `foliate-js`'s `view.open()` only sets up the renderer; it never renders any section by itself. No navigation call ever fired when there was no saved location and no Search/Notes jump target.
- **HA-003**: Frontend composition/CSS — a knock-on effect of the same fixed-offset assumption behind HA-004's root cause (see below); explicit header gap added as a second, independent safeguard.
- **HA-004**: Frontend layout/responsive composition — the toolbar title had no truncation and no shrink constraint.
- **HA-005**: UI composition — `.settings-panel` had zero CSS rules defined anywhere.
- **HA-006**: Component composition — the shared `TypographyPanel`'s CSS had one absolutely-positioned rule with no size cap, correct only for the Reader's floating-overlay use.
- **HA-007** (Batch #1): Reader theme propagation — `foliate-js` renders each EPUB section into an isolated document the app's `data-theme`/`prefers-color-scheme` CSS cascade cannot reach.
- **HA-007** (Batch #2, two further root causes found by real retest against the Batch #1 fix):
  - *App shell*: a Vite-template leftover, `@media (prefers-color-scheme: dark) { :root { ... } a:hover {...} input,button {...} }`, had no `:not([data-theme="light"])` guard. Its low specificity (0,1,0) is beaten by the canonical guarded rules (0,2,0) in every combination *except* explicit Light on a dark OS, where neither guarded rule applies and this unguarded leftover silently wins — exactly the reported symptom, and exactly why every other combination looked fine.
  - *EPUB body text*: the Batch #1 override (`html, body { color: ... !important }`) cannot reach a descendant element that sets its own `color` — CSS inheritance never applies to an element with its own explicit value, no matter how `!important` an ancestor's declaration is. Publisher stylesheets frequently set `color` directly on paragraph/heading elements, not just `body`.
- **HA-008**: CSS/component composition — `.typography-panel`'s only rule was `position: absolute; top: 3em; right: 1em; z-index: 10`, applied unconditionally to both the Reader-overlay and Settings-inline hosting contexts.
- **HA-009**: CSS specificity regression introduced by the HA-008 fix itself — `.reader .typography-panel { background-color: #f6f6f6; }` (2 classes) has higher specificity than the pre-existing dark-mode override `.typography-panel { background-color: #2f2f2f }` (1 class, inside `@media`), so the Reader's Aa overlay silently stayed light-backgrounded in every theme, while its labels correctly inherited the (dark-theme-correct) light foreground — light-on-light.
- **HA-010**: CSS/theme contract — contextual surfaces (Settings/Reader Typography, Reader Contents, Notebook, selection/completion overlays) each owned hard-coded light/dark backgrounds and scattered `prefers-color-scheme` overrides. Explicit Light could correctly reach the shell and EPUB content while component-level panel rules stayed on the wrong surface color. The correction establishes one shared contextual-surface token family for Light, Dark, and Match System.
- **HA-011**: Reader/foliate event-boundary integration — production Reader wiring covered initial open, TOC jumps, and view-mode attributes, and Batch #3 added host-level keyboard/wheel listeners, but a real EPUB's reading focus lands inside foliate-rendered section documents. Those iframe/shadow-boundary documents do not reliably bubble keyboard or wheel events to the host `document` / React shell, and the prior listener was also registered after the first `goToTextStart()`/`goTo()` could load the visible section. The installed `foliate-js` view API already owns navigation (`goLeft()`/`goRight()` for publication-direction-aware physical arrow directions, `prev()`/`next()` for reading-order movement), so the rework wires those APIs from each loaded section document before initial navigation rather than synthesizing CFI/fraction arithmetic.

## Minimal real-desktop retest checklist

Each item below is the smallest action that exercises the fixed code path in the actual native Tauri window (`start-dev.bat` or `npm run tauri dev`), matching each row's own Acceptance / Exit Evidence column from the original defect table.

1. **HA-001** — Open Library with zero Books, then import one Book, then create a Collection and filter to it. At every step: confirm no stray bullet/marker appears to the left of the Library content.
2. **HA-002** — Import a brand-new EPUB that has never been opened before (no saved reading position). Open it directly from the Library (not via Search/Notes). Confirm real body text is visible immediately, without first clicking a Contents entry. Then confirm existing behavior is unchanged: reopen a Book with a saved position (resumes there) and open one via a Search or Notes jump (jumps to that exact location).
3. **HA-003** — Open an EPUB with a populated Contents/TOC, click "Contents". Confirm the panel's title ("Contents") and its "Close" button are visually separated, not touching or overlapping.
4. **HA-004** — Open a Book with a long title (or rename one via Edit Title to something long). Confirm the title truncates (hover shows the full title as a tooltip) and every toolbar control (Focus, Contents, Aa, Sound, Notebook) remains visible and clickable.
5. **HA-005** — Open Settings. Confirm each section (Appearance, About & Updates, Actual Reading Time, Typography, Sound & Motion, Reading Checkpoint, Files & Data) renders as a visually distinct, spaced, grouped card rather than a flat list of raw controls.
6. **HA-006** — Open a Book, click "Aa". Confirm the Typography overlay is compact (does not dominate the reading surface) and scrolls internally if its content exceeds the panel height. Then open Settings -> Typography and confirm it renders inline in the page (not as a floating overlay), independent of the Reader's overlay behavior.
7. **HA-007** — On a Windows machine set to Dark mode (OS-level): open Settings -> Appearance -> Theme and select **Light** explicitly. Confirm the entire app shell (background, text, buttons) switches to light, not dark. Then open an EPUB and confirm body text is clearly readable against a light background. Switch Theme to **Dark** and confirm the shell and EPUB body text both go dark and stay readable, including after navigating via Contents, and including for a Book whose own publisher CSS sets colors on individual paragraphs/headings (not just relying on the page background). Switch Theme to **Match System** and confirm it follows the OS's actual current preference for both the shell and the EPUB text.
8. **HA-008** — Open Settings. Confirm Appearance is visible at the real top of the page, and scrolling down reaches About & Updates, Actual Reading Time, Typography, Sound & Motion, Reading Checkpoint, and Files & Data in order, with Typography never overlapping or hiding any other section. Then open a Book and confirm Reader's own Aa overlay still opens/closes normally.
9. **HA-009** — With Theme set to Dark (or Match System on a dark OS), open a Book and click "Aa". Confirm the overlay panel itself has a dark background and every label ("Font Source", "Size", "Line Height", etc.) is clearly readable against it, not invisible or low-contrast. Then switch to Light and confirm the panel returns to a light background with dark, readable labels.
10. **HA-010** — On a Windows machine set to Dark mode, select **Light** explicitly in Settings -> Appearance. Confirm the Settings inline Typography surface, Reader Aa Typography panel, Reader Contents panel, Reader Notebook panel, selection toolbar, and completion prompt all render as Light surfaces with readable dark text. Then select **Dark** and **Match System** on the same dark OS and confirm those same surfaces consistently render as Dark surfaces with readable light text.
11. **HA-011** — Open a real EPUB in paginated **Double Page** mode. Confirm Right Arrow advances and Left Arrow reverses; mouse wheel/touchpad down/forward advances and up/back reverses. Repeat the same basic check in **Single Page** mode. Switch to **Continuous Scroll** and confirm wheel/touchpad input scrolls naturally instead of forcing page turns. While focus is in toolbar controls or an overlay/panel, confirm arrow/wheel interactions are handled by that control/panel rather than hijacked for page turns. If an RTL publication is available, confirm physical ArrowLeft/ArrowRight follow the publication direction exposed by `foliate-js`.

A user checking off HA-007, HA-009, and HA-011 above as passing is what moves their status from ready-for-retest to `HUMAN-ACCEPTANCE CLOSED` — that transition is not self-granted by this session. HA-001 through HA-006, HA-008, and HA-010 are already recorded as `HUMAN-ACCEPTANCE CLOSED` per the user's own reported retest; their checklist items above remain useful as a full-suite regression check if a future change touches the same areas.
