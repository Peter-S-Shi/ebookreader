**M6 summary (full detail in `ROADMAP.md` Milestone 6 section):** a new `crates/domain/src/calendar.rs` module adds a day-keyed Calendar layer (`DESIGN.md` SS13, canonical `ER-CAL-001`) strictly on top of the existing M3 facts -- `record_active_reading_time_command` computes the same `active_duration` figure it always did and now folds it into both the per-book ledger (unchanged) and a new day-keyed aggregate, never a second independently-derived source of "how much was read." "Planned Book Hours" and "lightweight goals" were deliberately unified into one mechanism (a single global daily reading-time-goal number, no streaks/badges/per-book due dates), since frozen `PRODUCT_SPEC.md` SS9/SS15 defines no due-date/pacing algorithm to distribute per-book Book Hours across calendar days -- inventing one would have been an unlicensed product decision. Explainable historical reporting is structural: `daily_goal_history` is append-only and keyed by effective day, so `goal_in_effect_on` always resolves a past day to the goal actually in effect then, proven directly by a dedicated regression test (`changing_the_goal_does_not_retroactively_alter_a_past_days_planned_figure`). The Exit Gate's Stop/Escalate condition ("factual historical time would be retroactively altered") cannot trigger by construction -- the daily ledger only ever adds. A `Calendar.tsx` surface (month grid with activity dots, per-day Planned-vs-Actual detail card, goal editor) matches the accepted `docs/design/EbookReader_UI_Prototype_v0_5.html` Calendar composition and is wired into `App.tsx` as a toggleable section, consistent with the existing Notes toggle pattern. 10 new domain tests (134 total, was 124), 5 new frontend tests (68 total, was 63), CI green.

**M5 summary (full checkpoint history preserved in git log and `tooling/m5-evidence/`):** the reused PP-OCRv6 pipeline (detector, orientation classifier, recognizer) was root-caused past two double-activation bugs (sigmoid, then softmax) and a panicking `imageproc::geometry` dependency, ported into real production code (`crates/domain/src/ocr_{detect,recognize,classify,preprocess,engine}.rs`) with 3 real ONNX sessions composed in `OcrEngine::process_page()`, verified end-to-end against real fixtures including a real, public-domain, genuinely degraded 1893 page. Wired into a real Tauri command (`run_ocr_job_command`) and a dedicated `OcrWorkspace.tsx` surface (`DESIGN.md` SS10 canonical `ER-OCR-001`): Current Page / Selected Pages / Entire Book scope selection, a real thumbnail grid, real pause/resume/cancel, an always-visible correction card, Excerpt/Annotation capture on OCR'd text, and Library-wide Search indexing of OCR'd/corrected text. A column-aware reading-order fix (validated against the real fixture) closed multi-column English splicing; vertical-CJK reading order was root-caused to a detection-orientation problem (the detector finds cross-column horizontal bands, not per-column boxes) and explicitly carried forward as a residual needing a real architecture decision (rotation-reprocessing or a dedicated text-direction model), not a quick fix. The Exit Gate ("manual corrections survive raw OCR/cache rebuild and restart") is proven by two real automated tests, including one that closed a real gap in its own proof: every prior OCR test used an in-memory database (incapable of demonstrating restart survival at all), so a new test opens a real file-backed database, saves a correction, drops the connection, reopens a fresh one to the same file, and confirms the correction survived. **Self-correction:** M5 was first marked Complete at commit `51e506e` on Exit Gate/Success Evidence grounds alone; a follow-up self-review against `DESIGN.md`'s separate frozen UI-authority section found the OCR controls were folded into `PdfReader.tsx`'s page view rather than matching SS10's required dedicated-surface composition. This was caught and closed before any user or CI involvement -- a UI-composition-fidelity gap, not an Exit Gate defect -- by building the real `OcrWorkspace.tsx` surface described above, matching the accepted prototype's exact markup; this also closed the previously-open thumbnail-selection residual. Full Exit Gate evidence and residuals list: `ROADMAP.md` Milestone 5 section. 124 domain tests, 63 frontend tests, 2 local-only real-fixture integration tests, CI green on every M5 commit including the correction (`67d32c5`).
