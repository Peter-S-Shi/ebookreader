**This checkpoint (detector + postprocessing, both now ACCEPT):** per the user's explicit clarification that "Hold at M5" meant not skipping ahead to M6/M7/M8 while model-sourcing was unresolved (not a pause on M5 engineering itself), resumed the detector investigation directly. Root-caused the flat ~0.5-0.73 band from checkpoint 3: empirically ruled out the RGB/BGR channel-order hypothesis (a Python cross-check found bit-for-bit identical output either way), then found the real bug was a **double sigmoid** — `fetch_name_0` is already sigmoid-activated, and applying sigmoid again compresses [0,1] into [0.5, 0.731]. Fixing this in both a Python cross-check and the Rust `ort` harness produced a sane, spatially-varying map (min 0.0, max 0.9999, mean ~0.208) that matches almost exactly between the two. Detection tensor status: **ACCEPT**. Full findings: `tooling/m5-evidence/m5a_det_medium_rust_ort_spike.md`.

Then made and validated the postprocessing architecture decision (contour extraction + box scoring + polygon unclip, no Rust port existed before this checkpoint): `imageproc::contours::find_contours` + `geo-clipper` (Clipper-backed polygon offset) work correctly, but `imageproc::geometry::{convex_hull, min_area_rect}` (0.27.0) have confirmed total-order-violation panics on real DBNet contour data (measured: 32% of real contours lost to this bug before the fix). Replaced only those two calls with a ~70-line hand-rolled monotone-chain hull + rotating-calipers min-area-rect using `f64::total_cmp` (panic-proof by construction). End-to-end result on the real fixture: 142/142 boxes recovered (matching the Python reference's contour count exactly), zero panics. Full findings: `tooling/m5-evidence/m5b_postprocessing_architecture.md`. This postprocessing is now ported into production code — `crates/domain/src/ocr_detect.rs`, `detect_boxes(prob_map, width, height) -> Vec<DetectedBox>` — with 7 real unit tests against synthetic probability maps (single box, two separated boxes, below-threshold rejection, unclip expansion, panic-regression cases for the imageproc bug). This is pure geometry with no model dependency, so these tests run in CI without `ocr-assets/`. 98 domain tests total (was 91), all passing.
